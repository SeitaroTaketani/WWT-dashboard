# WWT dashboard — notes for Claude

UNCTAD 2.5D dashboard (Vite + Three.js + d3, static site) on trade and tariffs for water/wastewater treatment equipment.
English UI. UNCTAD house style is the top design priority. Read `README.md` for layout, commands and QA.

## Rules of the repo
- This repository is self-contained. Do not read from or write to sibling folders under `GitHub/`
  (the original `seaweedmap/wastewater/` and the SHC monitor repos are history, not dependencies).
- `public/data/*.json` and `scripts/validation.json` are generated by `npm run data` — change `scripts/process_wwt.py`
  or `data/raw/`, never the JSON. After a pipeline change the outputs must stay consistent with `src/data.js`
  (the duty logic `Data.dutyOn` / `Data.rateVector` is duplicated in the pipeline's validation block and checked by `qa/interact.mjs`).
- `dist/` and `qa/shots/` are git-ignored build/QA output.
- Commit and push only when asked; `main` auto-deploys to GitHub Pages.

## Gotchas
- **The UN TopoJSON is shifted −11.31° in longitude.** Real coordinates are rotated with `CONFIG.geoLonOffset`; walls are
  already in the map frame. Anything that mixes real lon/lat with the map geometry must apply the offset.
- Walls are stored in Equal Earth unit coordinates (y down): use `d3.geoEqualEarth().scale(1).translate([0, 0])`.
- `map3d.js` renders on demand: after changing the scene call `Map3D.invalidate()` (sets a dirty flag read by `_tick`).
  QA runs on software GL (SwiftShader), so its fps/timing numbers are pessimistic.
- The deep link is the URL hash (`#y=2024&p=all&d=MFN&r=Global&…`, see `src/deepLink.js`); `hashchange` reloads the page. 2D is the default view (`STATE.view`): only `v=3d` is written to the link, so older links without `v` open in 2D.
- Tunables (camera, wall height, arc widths, colours) live in `src/config.js` (`VIEW3D`, `CONFIG`).

## Verify a change
```bash
npm run lint                         # ESLint (no Prettier on purpose: the code is hand-formatted/dense, a reformat would touch ~30% of src)
npm test                             # build + serve dist/ on a free port + qa/interact.mjs (~40 checks incl. pipeline-vs-JS totals)
node qa/shots.mjs [baseUrl] [name]   # screenshots to qa/shots/ for visual review (desktop 1440/1920, mobile 390)
```
For manual runs, `npm run preview` serves `dist/` on :8080 (pass another base URL to the qa scripts if a stale preview holds 8080).
Rebuild `public/data` with `npm run data` (~2 min); outputs must stay byte-identical unless the pipeline logic changed on purpose.
Windows host: use absolute paths, and `PW_CHROME` to point at a Chromium if Playwright's own build is missing.
